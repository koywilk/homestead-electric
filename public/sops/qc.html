QC Walks

Walk it, call every item honestly, pick the verdict, decide who fixes it

The 30-second version

A QC walk is the quality gate on a phase. You walk the job, write down every item you find, and tag each one as a minor QC item or a QC miss or bigger item. Called items? The app suggests the verdict — passed with items or fail. A clean walk gets no suggestion: you pick QC Pass yourself. Then the one question that matters: is a return trip needed, or does the crew on site have it?

The walk, start to finish

1

Get it on the calendar

The job carries a QC status per phase: QC Needs to be Scheduled → QC Scheduled (with the date) → QC Completed. Unscheduled QC shows up in the nags until it has a date — schedule it, don't let it ride.

2

Walk and write — every item, as you find it

Add items on the walk screen the moment you see them. One item per real problem, written so someone who wasn't there can find it: "Master bath — GFI dead" beats "bathroom issue." Photo anything that's faster to show than tell.

3

Tag the severity on every item

Each item has a one-tap chip: Minor QC item (the default) or QC miss or bigger item. A miss is something that genuinely has to be made right before the phase can be called good — not a nitpick.

4

Confirm the verdict

If you called items, the app suggests a verdict from your severity tags — confirm it or override it. The picker is yours; the suggestion is just math. A clean walk gets no suggestion at all: pick QC Pass yourself in the status select. The walk doesn't record itself.

5

Answer the return-trip question

On anything that isn't a clean pass, the app asks: Create return trip or Crew on site has it. The rule: nobody on site → it's a return trip, every time. Crew still working the job → they take the list, no RT needed.

The three verdicts

VerdictWhen
QC Pass Clean walk — nothing called.
QC Passed with Items You called items, but none was a miss. Not a fail — but the list still has to get worked.
QC Fail At least one QC miss or bigger item. One real miss fails the walk — that's the rule, no matter how clean the rest was.

When the items later get fixed and checked off, the status moves to QC Items Fixed — Pass — and "checked off" means the walk's actual items, wherever they landed: on the return trip if one was made, with the on-site crew if they kept the list. Closing the last item is what earns the green, not the passage of time.

Why the severity chip is not optional

The chip decides two things at once: whether this walk can pass, and how the walk scores. A real miss tagged "minor" hides a return visit until it's an angry phone call — and minors aren't free either: they count now too, so forty little items is no longer the same as none. Call it what it is, both directions.

After the walk — who fixes what

·

Return trip path

Choosing Create return trip builds the RT with the walk's items on it. It shows on the Return Trips tab, and until someone gives it a date it sits on the Unscheduled Return Trips list and in the Forecast's Attention view under READY TO SCHEDULE — the items get closed on the RT like any punch list.

·

Crew-on-site path

Choosing Crew on site has it leaves the items with the working crew. Close them like punch items — check off, photo where it proves the fix.

·

Failed walk, no RT yet? The fail banner has your back

Any phase sitting at QC Fail shows a red QC FAIL — RETURN TRIP REQUIRED banner on the QC tab. It tells you where the return trip stands at a glance — none created, queued but needs a date, or scheduled — and when no RT exists yet it gives you a Create Return Trip button. One tap builds the RT with every open QC item, photos, severity, and material info carried over.

·

Item turns out not to be a real failure? Void it

Taken out during rough-in, out of scope, GC declined it — don't delete the item and don't check it off. Void it. Void asks for a reason (quick picks: Removed during rough-in, Not in scope, Fixed elsewhere, GC declined) and stamps who and when. A voided item drops out of the verdict, the return trip, and the QC counts, but stays in the punch list with a grey Voided pill and collects in the Voided (N) drawer on the walk screen. Wrong call? Restore brings it back in one tap.

The safety net

Answered Crew on site has it and the items are still open days later with no return trip covering them? The job flags them as Stranded QC Items in the Activity tab's to-do list. But the net only watches walks that gave that answer — a walk where the RT question never got answered can't trip it. So don't make the net do your job: answer the RT question honestly at walk time.

Do / Don't

Do

  • Write every item, even the small stuff — minors count now
  • Tag severity honestly, both directions
  • Photo anything a fixer would need to see
  • Make the RT call at walk time — nobody on site means RT
  • Schedule QC instead of letting it ride undated

Don't

  • Tag a real miss as minor to keep the walk green
  • Fail a walk that's all minor items — that's Passed with Items
  • Write "misc fixes" — nobody can find that on a slab
  • Leave the return-trip question for later
  • Delete or check off an item that wasn't a real failure — void it with a reason

Quick answers

The app suggested Fail but I think it's a pass-with-items.

The suggestion comes from your own severity tags — if there's a miss marked, it suggests Fail. Either fix the tag (it wasn't really a miss) or trust the call. You can override the picker, but the tags should match the verdict.

Minor items — do they really matter?

Yes. They count on the walk's score now, item by item. A walk with one miss and thirty minors is worse than one miss alone, and the numbers show it.

Crew said they'd fix it, then rolled off. Now what?

Make the return trip then — better late than lost. On a failed walk the QC tab shows the red QC FAIL — RETURN TRIP REQUIRED banner with a Create Return Trip button that carries the open items, photos, and severity over. Left sitting long enough, those items also surface as Stranded QC Items on the Activity tab's to-do list.

Rough QC vs Finish QC?

Each phase gets its own walk, own status, own verdict. A rough walk never concludes the finish walk.
