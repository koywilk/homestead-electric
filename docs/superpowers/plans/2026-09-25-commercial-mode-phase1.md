# Commercial Mode — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Work one task at a time, verify, then move on.

**Goal:** Ship the commercial division as a second mode of the same app: a `division` on every job (from Simpro's Business Group), a Resi / Commercial switch that filters every screen, a commercial job card with its own tabs, a commercial Job Board, the 12-phase **Job Start** pre-construction board with its Gear & Submittals and RFI logs, hats and My Day routing for Brady / Justin / Zane / Abe, automatic Drive folder + Simpro plan pull on commercial import, and server guards so residential nudges skip commercial jobs.

**Architecture:** One `jobs` collection, one doc shape. `division` and everything commercial live inside `job.data` (`data.division`, `data.commercial.*`) — no loader, rules, or collection changes. `App()` keeps the full array as `allJobs` and derives `jobs` (the current mode's jobs) once; every view keeps its `jobs` prop. Commercial tabs ride the v439 per-job tab mechanism (`tabsForJob`). The Job Start board is a new view modeled on `JobPrepTracker`; the current phase is **derived** from the checks (`commPhase(j)`), never stored. New hats ride `HAT_REGISTRY` + `ownersForRoute`; new auto-task rules ride `computeTasks`. Functions get one `isCommercialJob` guard and a weekly re-pull.

**Tech Stack:** React (single-file `src/App.js`), Firestore via the existing `saveJob` / `updateJob` funnel, inline styles with the `C` palette, Cloud Functions (`functions/index.js`), Vercel deploy, `vm`-extraction dry-run tests in `scripts/` wired into `prebuild`.

**Authorities:** Spec = `docs/superpowers/specs/2026-09-25-commercial-mode-design.md` (data model, decisions D1–D7, §6 Job Start process, §6.7 Drive, §9 answers). Visual / interaction reference = `commercial-mockup.html` (repo root, clickable, approved in conversation 2026-09-25). Where this plan and the spec disagree, the spec wins; where the mockup and the spec disagree on data, the spec wins; on look and feel, the mockup wins.
